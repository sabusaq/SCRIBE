SCRIBE

Sweep, Correlate & Report on IOCs, Batches, and Evidence.

Point this at a Windows forensic collection — KAPE, CyLR, Velociraptor, Aralez, or a raw/mounted drive — or a folder of many of them, and it runs the full triage pipeline: parse the standard artifacts, sweep your IOCs, detect with Sigma via Hayabusa, build a cross-artifact timeline, and write a findings report. Every artifact is accounted for in a named state, so you always know the difference between "nothing found" and "couldn't check."

PowerShell 5.1, no installation. Wraps Eric Zimmerman's tools and Hayabusa — SCRIBE is the layer that parses, correlates, scores, and reports on top of them.

1. What it does

Triage collectors (KAPE, CyLR, Velociraptor, Aralez) pull forensic artifacts off live Windows machines. SCRIBE is what you run after collection — it is not another collector, and not just a parser wrapper. For each collection it parses, detects, correlates, and reports, end to end:

StepAction
ResolveFinds the drive root inside the collection and validates it.
ParseRuns the right parser for each artifact in scope (MFT, Amcache, Prefetch, registry, event logs, ...).
DetectSweeps your IOC list across every parsed CSV; runs Sigma rules over the event logs via Hayabusa.
CorrelateOptionally builds a Timesketch-format super-timeline across all artifacts.
ReportWrites a coverage report and, optionally, a findings report per host and per batch.

Three design rules run through everything:

  • Coverage honesty. Every artifact ends in a known state. A "no hits" result on a thin collection is reported as inconclusive, never as clean.
  • Config over code. Layouts, artifacts, parsers, and defaults live in JSON under config/. Supporting a new artifact or collector layout is a config edit.
  • Evidence stays intact. Parsed CSVs are never modified or filtered in place. Derived views (timelines, filtered copies) are separate files.

2. Modes of operation

Single host

.\Invoke-Triage.ps1 -HostArtifacts D:\case\HOST01 -ToolsPath C:\Tools\ZimmermanTools -IocFile .\iocs.txt

Analyzes one already-extracted collection.

Batch

.\Invoke-Triage.ps1 -BatchFolder D:\evidence -ToolsPath C:\Tools\ZimmermanTools `
  -Hayabusa C:\Tools\hayabusa\hayabusa.exe -IocFile .\iocs.txt -OutputPath D:\out

Analyzes a folder of collections - archives (.zip .7z .tar.gz .rar), already-extracted folders, or a mix. Archives are extracted, analyzed, and the extracted copy deleted (-KeepExtracted retains it). Extracted folders are analyzed in place and never deleted. A corrupt collection is marked FAILED and the batch continues. Before starting, a disk capacity check estimates peak usage and hard-stops if the output drive is too small (-Force overrides).

Batch results are aggregated: a global IOC timeline (which host, which indicator, when), a host-by-indicator matrix, a per-host coverage table, and optionally a batch findings report.

Every external tool call is timed, logged to _logs\<tool>.log including the exact command line, and is non-fatal: one failed parser never aborts a host, one failed host never aborts a batch.

4. Collection layouts

-Layout defaults to Auto, which tries every known drive-root pattern (top-level C\/D\, URL-encoded C%3A, Velociraptor uploads\... paths, and the folder itself) and announces how it resolved. Named layouts force a specific structure:

LayoutCollectorDrive root location
Auto(default)resolved automatically, printed on screen
AralezKaspersky GERT<collection>\C\
KAPEKroll KAPE<machine>\C\ or C%3A\
CyLRCyLR<host>\C\
VelociraptorVelociraptoruploads\...\C:\
Rawmounted image / Windows.oldthe folder itself

If the chosen layout's anchor ($MFT / Windows\System32) is not found, the run stops with the list of paths it tried. Layout definitions are in config\layouts.json; adding a collector is one JSON block. See docs-LAYOUTS.md for folder diagrams.

5. Artifacts & tiers

The artifact catalog is config\artifacts.json: each entry maps a logical name to path patterns, a parser (from config\parsers.json), and a tier. The run parses everything at or below the selected tier.

TierArtifacts
default$MFT, $J (UsnJrnl), Amcache, Prefetch, Registry (RECmd + Kroll batch), Scheduled Tasks, Event Logs
extended+ Shimcache, SRUM, Shellbags, Recycle Bin
full+ LNK, Jump Lists, NTUSER
optional$LogFile, $Secure, $Boot - added explicitly via a scope config

Artifact paths are tried at their configured locations first; if not found, a filename-based discovery search runs (skipping VSS / Windows.old / RegBack copies), and any discovered path is flagged on screen. -NoDiscover disables the fallback.

6. Detection: IOCs and Sigma

IOC sweep

-IocFile takes one or more files or a folder. One indicator per line, # comments. Hashes (MD5/SHA1/SHA256), filenames, IPs, domains, paths, or any string (e.g. a command-line fragment). Indicators are typed at load: hashes, IPs, and domains match on word boundaries and are reported as high confidence; everything else is a case-insensitive substring match reported as low confidence. The sweep covers every parsed CSV - an Amcache SHA1 column, an MFT path, an event payload - and each hit records the host, the indicator, the artifact, the line, and a timestamp taken from the artifact's known time column, tagged with its semantic. A row carrying several indicators produces one hit per indicator.

Short or partial-hex indicators (not 32/40/64 chars) are flagged at load time because they collide with Windows GUIDs and device IDs. On metadata-only collections, SHA1 indicators are the ones that produce hash-level confirmation (Amcache stores SHA1).

An empty IOC set is a valid run - Sigma still provides detection.

Sigma via Hayabusa

When -Hayabusa points at the exe, the event logs are scanned with Hayabusa's bundled Sigma rule set (all rules enabled), producing:

  • Hayabusa_Detections.csv - only rule matches. "Is anything bad?" Sort by level.
  • Hayabusa_DFIR_Timeline.csv - a chronological event timeline. "What happened, in order?"

Custom Sigma rules go into Hayabusa's rules\ folder, or run standalone with hayabusa.exe csv-timeline -r <your rules>.

7. Coverage model

Every artifact in scope ends in exactly one state:

StateMeaning
ParsedTool ran, exited 0, and produced non-empty output.
NotInCollectionThe artifact was not in the package. Blind spot.
ToolMissingNo parser found under -ToolsPath. Blind spot.
NoOutputTool ran but wrote nothing (some tools exit 0 on failure). Blind spot.
ParseFailedTool errored or the path was invalid. Blind spot.
SkippedByConfigDeliberately skipped by the scope config. Declared blind spot.

If none of the core artifacts (MFT / Amcache / UsnJrnl / EventLogs) parsed, the run result is INCONCLUSIVE regardless of IOC results. The default posture is neutral: the engine reports matches and coverage; it does not declare a host infected.

8. Timelines & time window

-Timeline case writes one Timeline_Timesketch.csv per host; -Timeline global writes one _GLOBAL_Timeline_Timesketch.csv across a batch with a host column. Format is Timesketch-native (message, datetime, timestamp_desc, data_type, host) and loads directly into Timesketch or Timeline Explorer. Sources: MFT ($SI/$FN timestamps), $J, Amcache, Prefetch, Registry key writes, and event logs.

-TimelineStart / -TimelineEnd (ISO 8601) bound the window. A full-MFT unbounded timeline is millions of rows; bound it. With -FilteredCopies, the engine also writes *_filtered.csv beside each artifact CSV containing only the rows in the window - the full CSVs are never modified, and filtered copies are excluded from the IOC sweep so hits are not double-counted.

9. Reports

-Report produces fully automatic, ready-to-read HTML (open in Word to save as .docx; print to PDF):

  • Per host - Findings_Report.html: auto-written executive summary (states IOC match count, distinct indicators, artifact sources, earliest/latest matched activity, critical/high Sigma count - or "inconclusive" when core artifacts are missing), coverage table, IOC match table, top 5 critical/high detections, and blind spots.
  • Per batch - _GLOBAL_Findings_Report.html: findings per host (hit rows highlighted), earliest observed IOC-matched artifact time per host (mixed timestamp semantics; not proof of infection order), and which indicators appeared on how many hosts.

Templates are plain HTML/CSS under templates\ - restyle once (letterhead, colors) and every report inherits it.

13. Requirements

  • Windows PowerShell 5.1+
  • Eric Zimmerman's tools: MFTECmd, AmcacheParser, PECmd, EvtxECmd, RECmd + Kroll_Batch.reb (core); AppCompatCacheParser, SrumECmd, SBECmd, RBCmd, LECmd, JLECmd (extended/full tiers)
  • Hayabusa (optional - Sigma + DFIR timeline)
  • 7-Zip (optional - batch mode with non-.zip archives)

A pre-flight check reports which tools were found; missing tools mark their artifacts as blind spots rather than failing the run.
